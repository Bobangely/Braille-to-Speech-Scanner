# จังหวะอ่านภาษาไทยด้วย Edge

แก้เฉพาะเส้นทางปุ่ม S → Edge worker; ข้อความบนจอ, Decoder, Thai Assembly และ offline TTS คงเดิม
ช่องว่างหลายช่อง/newline ยังอยู่หลัง `prepare_thai_speech_text`; เดิมส่ง Edge ครั้งเดียวโดยไม่มี pause ที่กำหนดเอง
`edge-tts` 7.3.1 ที่ติดตั้ง escape ข้อความใน `communicate.py` ก่อนสร้าง SSML จึงไม่ส่ง `<break>` เป็นข้อความ

ค่า config อยู่ที่ `edge_stream.THAI_PAUSES_MS`:

ความเร็วออกเสียงจริงกำหนดที่ `piper_tts.EDGE_RATE` ปัจจุบัน `-15%` เป็นค่าเริ่มต้นของโปรเจกต์ (default ของบริการ Edge คือ +0%)
การเปลี่ยนค่า pause เพียงอย่างเดียวไม่เปลี่ยนอัตราพูดของ Edge
rate ถูกส่งใน job ไป worker และอยู่ใน cache key จึงไม่ใช้เสียงเก่าหลังเปลี่ยน rate

| ขอบเขต | Silence ที่แทรก |
|---|---:|
| ช่องว่างหนึ่งช่อง | 0 ms — รวมคำในวลี |
| หลายช่องหรือ tab | 0 ms — รวมคำในวลี |
| newline / CRLF | 10 ms |
| `. ! ? ฯ` | 50 ms |

หากขอบเขตซ้อนกันใช้ค่ามากที่สุด ไม่รวมบวกกัน; ไม่มี silence นำหน้าหรือท้าย job
รองรับทศนิยม 0–5000 ms และปัดเป็นจำนวน sample ที่ใกล้ที่สุดที่ 24 kHz; 0.5 ms เท่ากับ 12 samples
ขอบเขตที่มีค่า 0 ms รวมส่งในคำขอเดียว เพื่อลดจังหวะ/เวลารอที่เกิดจากการแยก synthesize แต่ละกลุ่มคำ
จุดระหว่างตัวเลข เช่น 3.14 ไม่ใช่ขอบเขตประโยค ไม่ตัดคำไทยภายในกลุ่มคำ
ชื่อพยัญชนะ 44 ตัวขยายก่อนแบ่งเสียงตามกฎเดิม

ดาวน์โหลด MP3 ตามลำดับใน worker และเริ่มเล่น chunk แรกระหว่างดาวน์โหลด
สำหรับภาษาไทย ตัดเฉพาะ PCM ที่เป็นศูนย์ล้วนบริเวณหัว/ท้าย chunk ก่อนแทรก silence ตาม config
เก็บทุก sample ที่ไม่เป็นศูนย์ รวมถึงเสียงเบา และเก็บความเงียบภายใน chunk ไว้ ไม่ใช้ threshold หรือแก้ข้อความ
ใช้ PlaybackDevice เดียวตลอด job ไม่โหลดโมเดลในเครื่องต่อ chunk
แต่ละกลุ่มยังต้องส่งคำขอ Edge ใหม่; คำขอถัดไปเริ่มได้หลังรับ MP3 กลุ่มก่อนครบ โดยมี queue จำกัดสองกลุ่ม
แทรก silence เป็น PCM 24 kHz แล้วรวมใน WAV cache; เปลี่ยน config ทำให้ cache เดิมไม่ถูกใช้
ปุ่ม B หยุด worker/process tree เดิม รวมทั้งช่วง silence; ไม่มี sleep บน UI thread
เสียงอังกฤษยังไม่แบ่ง pause แบบไทย แต่ใช้ Edge rate เดียวกัน; เส้นทาง local Piper/MMS ไม่เปลี่ยน

ค่าข้างต้นคือ silence ที่แทรกเพิ่ม ไม่รับประกันระยะพักรวม เพราะ Edge มีจังหวะของเสียงเองและอาจต้องรอเครือข่าย
เครื่องหมายจุดที่เป็นคำย่อยังอาจถูกมองเป็นท้ายประโยค ให้ทดสอบเอกสารจริงก่อนปรับค่า

## Speech error กับรายการที่ขึ้นต้นด้วยเครื่องหมาย

พบว่าการแบ่ง `- คำควบกล้ำตัว` เคยส่ง `-` เป็นคำขอเดี่ยว ทดสอบ Edge Niwat จริงแล้วได้ `NoAudioReceived`
จึงรวมกลุ่มเครื่องหมายที่ไม่มีตัวอักษร/ตัวเลขไว้กับคำข้างเคียง เช่น `- คำควบกล้ำตัว` โดยไม่ลบเครื่องหมายหรือแก้ข้อความบนจอ
กรณีนี้เกิดจากการแบ่ง chunk ไม่ได้ยืนยันว่า B เป็นสาเหตุของ error ในภาพ เพราะไม่มี worker log ของครั้งนั้น
ยังคงรายงาน error จากเครือข่าย/บริการตามจริง ไม่ข้าม chunk ที่อ่านไม่สำเร็จเงียบ ๆ

## ผลวัด Windows วันที่ 16 ตุลาคม 2026

ผลวัดต่อไปนี้เป็นของค่าพักชุดแรก 250/425/600/700 ms ก่อนลดเป็นค่าปัจจุบัน:
ข้อความเดียวกัน `เขียด เขียว  ขอน\nไข่.` ใช้ Niwat ความเร็ว -15%:

- ก่อนแก้: first audio 1.09 s, WAV 3.504 s
- หลังแก้: first audio 1.26 s, WAV 8.475 s, 4 chunks, silence เพิ่มรวม 1.275 s
- วัดซ้ำผ่าน controller: first audio 0.88 s; S ระหว่างรอใช้ PID เดิม
- S จาก cache พร้อม marker 0.247 s; B คืนค่าใน 0.0021 s และหยุด worker tree ได้; อ่านหลัง B ใช้ cache ได้

เป็นการวัดครั้งเดียวต่อกรณี ไม่ยืนยันว่า latency ไม่เพิ่มหรือเสียงเป็นธรรมชาติขึ้นสำหรับทุกข้อความ
WAV ที่ยาวขึ้นรวมจังหวะที่ Edge สร้างให้แต่ละ chunk ด้วย ไม่ใช่ silence config เพียงอย่างเดียว
ยังไม่ได้ประเมินการออกเสียงด้วยผู้ฟังหรือทดสอบบน Linux ARM64

## Q ขณะไฟล์เสียงยังถูก Windows ล็อก และความเร็วจริง

Traceback ที่พบคือ `PermissionError [WinError 32]` ขณะ cleanup `speech.wav`
เดิม exception หลุดจาก `stop()` ทำให้ Q ถูกมองเป็น ACTION FAILED และ scanner ไม่ออก
ตอนนี้หยุด worker ก่อน เคลียร์สถานะอ่าน แล้วเลื่อน cleanup เฉพาะ temporary directory ที่ตัวเองสร้างไว้
หากไฟล์ยังล็อก จะบันทึก warning และลองใหม่เมื่อ stop ครั้งถัดไป โดยไม่หน่วง UI เพื่อรอไฟล์
ถ้ายังล็อกจนปิดโปรแกรม อาจมีไฟล์ชั่วคราวเหลืออยู่; ไม่ลบไฟล์จากโฟลเดอร์อื่น

ทดสอบ Windows โดยเปิดล็อก WAV ไว้จริง: Q คืนค่าออก, worker หยุด, ไม่มี ACTION FAILED
หลังปลดล็อก การเรียก stop ซ้ำลบ temporary directory ได้
ทดสอบข้อความ `เขียดเขียวเกาะขอน` ผ่าน Edge Niwat โดยไม่แบ่งคำ เพื่อแยก rate ออกจาก pause:

| Rate | WAV | เริ่มเสียง |
|---|---:|---:|
| -15% | 2.352 s | 0.983 s |
| +0% | 1.992 s | 0.975 s |

เป็นผลวัดครั้งเดียวต่อ rate ไม่ยืนยัน latency เครือข่ายทุกครั้ง
การแบ่งหลาย chunk ยังอาจมีช่องว่างจาก Edge/เครือข่ายมากกว่า silence ที่ตั้งไว้
รอบแก้ Q/rate ผ่าน regression 458 tests รวมทดสอบล็อกไฟล์ Windows จริง และ S ซ้ำ/B ผ่าน Edge จริง

## ลดช่วงพักโดยคงเสียง -20%

ผลส่วนนี้เป็นประวัติขณะตั้ง -20%; ปัจจุบันใช้ -15%
ไฟล์จาก Edge มี padding เงียบติดมาด้วย จึงไม่พอที่จะลดเฉพาะ silence ที่แทรกเอง
วัดข้อความ `เขียด เขียว  ขอน\nไข่.` ที่ -20% และ pause 10/30/50/100 ms เหมือนกัน:
ก่อนตัด padding WAV 7.290 s → หลังตัด 7.073 s; ทั้งคู่เพิ่ม silence จาก config รวม 0.090 s
เป็นผลวัดครั้งเดียว ไม่ยืนยันความเป็นธรรมชาติโดยผู้ฟัง และการรอคำขอ Edge ยังทำให้ช่วงพักจริงยาวขึ้นได้
การตัด padding ทำขณะ streaming ไม่ต้องรอสร้างเสียงครบก่อนเริ่มเล่น

## กลับสู่ default และแก้บัฟเฟอร์สะดุด

หลังตัด padding พบว่าขนาด block อาจเล็กกว่าที่ PlaybackDevice ขอ จึงเพิ่มการรวมบัฟเฟอร์ให้ครบทุกครั้ง ยกเว้น block สุดท้าย
รักษาลำดับ sample เดิมและ silence ตาม config; เปลี่ยนขนาด callback ได้โดยไม่ทำเสียงหล่นหรือเพิ่มช่องเงียบระหว่าง block
รอบแก้บัฟเฟอร์ใช้ Edge +0% และพัก 0/10/20/50 ms; ปัจจุบันใช้ -15% และพักเฉพาะบรรทัด 10 ms / ท้ายประโยค 50 ms
ค่า space ที่มากกว่า 0 ms จะแยกคำขอที่ช่องว่างเดี่ยว ต่างจาก 0 ms ที่รวมคำขอ จึงอาจรอเครือข่ายมากขึ้นแม้ silence สั้นมาก
ผ่าน 460 regression tests; ทดสอบ Edge จริง S ซ้ำใช้ worker เดิม, B หยุด worker ได้ และอ่านจาก cache หลัง B ได้
ยังไม่ได้ประเมินความลื่นด้วยผู้ฟัง และไม่ได้รับประกันเวลารอของบริการ Edge

## รวมคำในวลีเพื่อลดการรอ Edge

ค่าเริ่มต้นรวมคำที่คั่นด้วยช่องว่างหนึ่งช่อง/หลายช่อง/tab เป็นคำขอเดียว แยกคำขอเฉพาะ newline หรือ `. ! ? ฯ`
ใช้กลไกรวมขอบเขต 0 ms เดิม ไม่เปลี่ยน decoder, ข้อความบนจอ, ชื่อพยัญชนะ 44 ตัว หรืออัตราพูด -15%
ช่องว่างในข้อความสำหรับส่งเสียงถูกรวมเป็นช่องเดียวระหว่างกลุ่มคำ แต่เก็บตัวอักษร/ลำดับคำเดิม
ยังรองรับค่า pause ทศนิยมเมื่อกำหนดเอง แต่ค่าบวกที่ช่องว่างจะกลับไปสร้างคำขอแยก
pause บรรทัด/ท้ายประโยคคือ silence ที่แทรกเพิ่ม ไม่ใช่การรับประกันระยะพักจริงของบริการ

ผลวัด Windows ด้วย Edge Niwat -15% และข้อความ `เขียด เขียว  ขอน\nไข่.`:
แบบเดิม 0.5/5/10/50 ms ใช้ 4 คำขอ อ่านจบรวม 8.284 s, WAV 7.012 s
แบบรวมคำใช้ 2 คำขอ อ่านจบรวม 4.451 s, WAV 3.510 s
เป็นการวัดครั้งเดียวต่อแบบ เวลาเริ่มเสียง 0.979 / 0.641 s ตามลำดับ ไม่รับประกันความเร็วเครือข่ายทุกครั้ง
ทดสอบ S ซ้ำใช้ worker เดิม, B หยุด worker และอ่านซ้ำหลัง B จาก cache ได้

ทดสอบด้วย `python -X utf8 -m unittest discover -s tests -q`
ผลรอบสุดท้ายผ่าน 455 tests และ syntax / `git diff --check` ผ่าน
รวม tests ตรวจลำดับ PCM, ระยะ silence ทั้งสี่แบบ, เครื่องเล่นเดียว, cache/config, S/B, 44 ตัว และข้อความต้นฉบับ
