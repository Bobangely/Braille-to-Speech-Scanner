# อ่านเฉพาะเบรลล์ที่แต้มสี

แก้บน branch `codex/colored-braille-only` จาก `main` โดยให้เส้นทางกล้องและภาพเดี่ยวอ่านเฉพาะจุดสี ค่าเริ่มต้นเป็นสีน้ำเงิน เลือกแดง เขียว หรือหลายสีได้

## สาเหตุและบทบาทของ YOLO เดิม

เส้นทางเดิม: Camera → ROI/ปรับความคม → YOLO ตรวจจุด → จัดบรรทัดและเซลล์ → crop → YOLO ตรวจจุดใน crop → รวม marker → decoder → UI

โมเดลมี class `braille_dot` เพียง class เดียว จึงตรวจจุด ไม่ได้จำแนกตัวอักษรไทยหรือหา cell โดยตรง การสร้าง cell มาจาก geometry ของจุดที่โมเดลเสนอ

เส้นทางใช้งานเดิมไม่ได้ตรวจสี จุดนูนที่ไม่มีสีจึงเข้าสู่ geometry และ decoder ด้วย หากอ่าน crop ไม่ได้หรือกริดกำกวม ตัว decoder จะสร้าง `�` (U+FFFD) พร้อมเหตุผล เมื่อไม่รู้จัก pattern ก็อาจมีเครื่องหมายแทนตัวอักษรที่อ่านไม่ได้ อาการนี้เกิดก่อน rendering ไม่ใช่การแปลงอักษรไทยทุกตัวเป็น `?` เพราะฟอนต์

## เส้นทางใหม่

Camera/ภาพดิบ → ROI/ปรับความคมเดิม → ตรวจจุดสี → กรอง component ที่ไม่ใช่จุด → จัดบรรทัดและกริดเซลล์จากจุดสีเท่านั้น → จับตำแหน่ง 1–6 → รวม marker ที่อยู่ติดกัน → decoder ไทย/อังกฤษ → UI

```text
1 4
2 5
3 6
```

เซลล์ไม่มีสีไม่ถูกสร้างตั้งแต่ต้น จึงไม่ถึง decoder และไม่สร้างอักขระแทนการอ่านไม่ได้ ไม่ได้แก้ด้วยการลบ `?` หรือ `�` ที่ UI

เลือกจัดกลุ่มจากจุดสีโดยตรง เพราะเก็บหลักฐานสีและพิกัดได้อยู่แล้ว การรัน YOLO ซ้ำใน crop จะเพิ่มโอกาสนำจุดนูนไม่มีสีกลับมาอ่าน ตัวอ่านสีจึงไม่โหลดหรือรันโมเดล YOLO แต่ใช้ OpenCV สำหรับการตรวจสีและจัดการภาพ และใช้ geometry/decoder เดิมร่วมกัน

ชื่อคลาส `YOLOBrailleDetector` ยังคงไว้เพื่อรักษา call sites เดิม ส่วน `dot_color=None` เป็นการเลือกเส้นทาง YOLO เดิมอย่างชัดเจนสำหรับประเมินโมเดล เครื่องมือ benchmark และตัวสร้างภาพ annotated สำหรับโมเดลเลือกเส้นทางนี้แล้ว

## วิธีตรวจสีและจัดเซลล์

- ตรวจภาพ BGR uint8 และแปลงเป็น HSV แยก hue ของสีที่เลือก กรอง saturation ต่ำกว่า 60 และ value ต่ำกว่า 15 เพื่อตัดกระดาษ/เงาที่ไม่มีสี
- ใช้ morphological closing ขนาด 3×3 เชื่อมรอยขาดเล็กน้อยของสี โดยไม่ใช้ opening ที่อาจลบจุดขนาดเล็ก
- แยก connected components กรองพื้นที่ 6–8000 พิกเซล อัตราส่วนด้านไม่เกิน 3 และสัดส่วนพื้นที่สีในกรอบไม่น้อยกว่า 0.2 เมื่อมีอย่างน้อย 4 components จะกรอง noise ตามขนาดมัธยฐานด้วย
- ใช้ศูนย์กลางของจุดสี ประเมินระยะจุดและมุมเอียง แบ่งแถวเป็นบรรทัดก่อนจัดสองคอลัมน์ จับคู่จุดกับ slot ที่ใกล้และอยู่ในระยะยอมรับ
- เรียงบรรทัดก่อน แล้วซ้ายไปขวา ใช้ mapping ไทยเดิม เช่น marker 6 ตามด้วย 13456 เป็น ญ เมื่อหลักฐานและความติดกันรองรับ
- จำกัดระยะการรวม marker ตามระยะจุดด้วย เพื่อไม่ให้การกรองเซลล์ไม่มีสีทำให้ marker กระโดดไปรวมกับเซลล์ไกลหรือข้ามบรรทัด

การกรองสีไม่ได้ยืนยันว่าจุดสีทุกจุดเป็นเบรลล์ หากกริดของส่วนที่แต้มสีกำกวม ระบบยังรายงานความไม่แน่ใจตาม decoder เดิม ไม่เดาคำแทนผู้ใช้ จุดเดี่ยวที่ไม่มีกริดอ้างอิงอาจไม่สร้าง cell ส่วนบรรทัดที่มีจุดไม่ครบแถวอาจยังต้องปรับ ROI เพื่อให้มีบริบทเพียงพอ

## วิธีทดสอบ

เปิดกล้องจากโฟลเดอร์โปรเจกต์:

```powershell
.venv\Scripts\python.exe camera_reader.py --lang thai --res fhd --sharp 0 --dot-color blue
```

ภาพเดี่ยว:

```powershell
.venv\Scripts\python.exe yolo_detector.py path/to/raw_image.png --lang thai --dot-color blue --save --dump-stream
```

เปลี่ยน `blue` เป็น `red` หรือ `green` ตามหมึก ใช้ `auto` เมื่อมีหลายสีในหน้าเดียว รวมถึงหลายสีภายในเซลล์เดียว โหมดนี้รับสีอื่นในภาพได้มากขึ้นด้วย สีดำ/เทาไม่ใช่หลักฐานสีที่ตัวอ่านนี้ใช้แยกจากเงากระดาษ

กด `D` ในกล้องเพื่อบันทึกภาพ input ที่อ่านจริง, camera ROI, ภาพผลลัพธ์, crop รายเซลล์ และ `manifest.json` รายงานมีสี/ช่วง threshold, จำนวน components, จุดที่ยอมรับ, ตำแหน่ง slot, Unicode ของข้อความ และเหตุผลความไม่แน่ใจ โดยระบุ `yolo_inference=false` และ `crop_role=diagnostic_view` สำหรับตัวอ่านสี

## ผลตรวจอัตโนมัติ

- Full suite: ผ่าน 85 tests รวมกรณีสีบางส่วน ขอบขาด noise เล็กน้อย จุดเล็ก/เบลอเล็กน้อย มุมเอียง 5° perspective เล็กน้อย หลายบรรทัด และช่องว่างระหว่าง marker
- ภาพสังเคราะห์ที่มีเซลล์เทา 8 ตัวด้านบนและ 8 ตัวด้านล่าง กับเซลล์สีน้ำเงิน 4 ตัวตรงกลาง: ส่งออกเฉพาะ 4 เซลล์สีน้ำเงิน แปลเป็น `กญา` โดยเซลล์เทาไม่เข้าสู่ decoder
- ภาพไม่มีสีให้เซลล์ว่างและข้อความว่าง การสลับเฟรมมีสี → ไม่มีสี → มีสีใน worker ไม่ค้างข้อความเก่าและกลับมาอ่านได้
- Legacy YOLO benchmark ผ่าน 99/99 ภาพ คะแนนนี้เป็น regression ของโมเดลบนชุดสังเคราะห์ แยกจากการประเมินตัวอ่านสี

ภาพสาธิตและ manifest อยู่ใน `scratch/colored_only_20260911/mixed_page/` ส่วนผล benchmark อยู่ใน `scratch/colored_only_20260911/yolo_regression.json` ไฟล์ใน scratch เป็นผลตรวจภายในเครื่อง ไม่ใช่ข้อมูลฝึกใหม่

## สิ่งที่ยังต้องทดสอบกับหนังสือจริง

ยังไม่ได้ยืนยันความแม่นยำหรือ FPS กับกล้องจริงและบอร์ด Redxa ต้องใช้ภาพดิบที่ไม่มี overlay ทดสอบหมึกจริง แสงเงา white balance สีจาง ขนาดจุด ระยะห่าง รูปทรงสีที่แต้ม และมุมกล้อง ค่า threshold ปัจจุบันเป็นจุดเริ่มต้นที่ผ่านภาพสังเคราะห์ ยังไม่ใช่ค่าที่ปรับจากหนังสือจริงแล้ว

ภาพตัวอย่างที่ผู้ใช้แนบมีกรอบ เส้น และข้อความสีจาก debug อยู่แล้ว สิ่งเหล่านี้อาจถูกอ่านเป็นสี จึงใช้ตรวจอาการได้ แต่ไม่ใช้เป็นภาพอ้างอิงเพื่อวัดความแม่นยำหรือปรับ algorithm ตามตำแหน่ง C23–C30 ตัว camera pipeline ใช้เฟรมก่อนวาด overlay

ภาพเบลอจนสีหรือระยะจุดหายไป จุดสีรบกวนขนาดใกล้เคียงจุดเบรลล์ และการเลือกสีผิดยังทำให้อ่านไม่ได้ได้ การทดสอบรอบถัดไปควรเก็บด้วยปุ่ม `D` เพื่อแยกปัญหาสีออกจาก geometry และ mapping ด้วยหลักฐานจากเฟรมเดียวกัน
