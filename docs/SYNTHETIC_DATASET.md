# รีวิวภาษาไทย: YOLO เท่านั้น และ dataset เบรลล์ไทยสังเคราะห์

ทำบน branch `codex/yolo-cell-stream` เพื่อเตรียมฝึกโมเดลเป็นรอบระหว่างรอหนังสือเบรลล์จริง

## 1. โปรแกรมเปลี่ยนอย่างไร

กล้องและตัวอ่านภาพใช้ YOLO เป็นตัวตรวจจับเดียว ถอดเส้นทางตรวจสี HSV, contour, Hybrid และ fallback ไป CV ออกจากโปรแกรมแล้ว รวมทั้งปุ่มเปลี่ยนโหมด/เปลี่ยนสีที่ใช้กับ CV ตัวอ่านภาพ `main.py` ก็ใช้ YOLO เช่นเดียวกับกล้อง

โค้ด CV และการทดสอบ CV เก็บเป็นประวัติใน `archive/legacy_cv/` ไม่ถูกเรียกจากโปรแกรมหรือชุดทดสอบปัจจุบัน ส่วน `cv2` ยังเป็น dependency สำหรับเปิดกล้อง อ่านไฟล์ ย่อ/หมุน/crop ภาพ และวาดภาพ ซึ่งเป็นงานเตรียมภาพ ไม่ใช่ตัวตรวจจับเบรลล์

โมเดลปัจจุบันมี **คลาสเดียว `0 = braille_dot`** จึงสร้าง dataset สำหรับตรวจจุดให้ต่อยอด weights เดิมได้ YOLO ตรวจจุด → สร้าง crop เซลล์ → YOLO อ่าน crop → จับคู่ marker เช่น ญ/ศ/ภ/ธ → ประกอบข้อความ ยังไม่ได้เปลี่ยนโมเดลเป็นตัวตรวจกรอบเซลล์หรือจำแนกตัวอักษรโดยตรง

เมื่อระบุไฟล์โมเดลทดลองแล้วไฟล์นั้นใช้ไม่ได้ โปรแกรมจะรายงานข้อผิดพลาด ไม่เปลี่ยนไปใช้โมเดลหลักโดยเงียบ ๆ

เพิ่ม dependency ของ YOLO และ YAML ใน `pyproject.toml` พร้อมปรับ `uv.lock` และตรวจว่าทั้งสองไฟล์สอดคล้องกันแล้ว

## 2. ชุดข้อมูลที่สร้างจริง

โฟลเดอร์: `datasets/thai_synthetic/seed_20260908/` ขนาดประมาณ **111.8 MiB**

| ชุด | จำนวนภาพ | ใช้ทำอะไร |
|---|---:|---|
| train | 2,400 | ปรับ weights ของโมเดล |
| validation | 300 | เลือกรอบฝึก/พารามิเตอร์และตรวจว่าการฝึกดีขึ้นหรือไม่ |
| test | 300 | ประเมินตอนจะเลือกโมเดลใช้งาน ไม่ใช้ปรับแต่งทุกครั้ง |
| รวม | 3,000 | มาจากฉากต้นแบบ 1,500 ฉาก ฉากละ 2 ภาพแปรรูป |

มี label จุดทั้งหมด **85,438 จุด** และภาพไม่มีจุดเบรลล์ **446 ภาพ** ตัวนับนี้รวมหน้าว่างที่เกิดขึ้น 2 ภาพด้วย ส่วนข้อมูลชนิดฉากที่ตั้งใจสร้างแบ่งเป็นหน้ากระดาษ 1,816 ภาพ, เซลล์เดี่ยว 740 ภาพ และฉากรบกวนที่ไม่มีเบรลล์ 444 ภาพ

ตัวอย่างจำนวนภาพที่มีรายการฝึกแต่ละตัว: ญ 690, ศ 714, ภ 680, ธ 752 ภาพ ตัวเลขเหล่านี้นับซ้อนกันได้เมื่อภาพเดียวมีหลายตัว และรวมภาพแปรรูปจากฉากเดียวกันด้วย

ชุดข้อมูลมี:

- หน้ากระดาษ 1–3 บรรทัด ระยะเซลล์/ระยะบรรทัดหลายแบบ
- พยัญชนะไทย ตัวอักษร 2 เซลล์ สระ วรรณยุกต์ สัญลักษณ์ และตัวเลข
- ภาพเซลล์เดี่ยวบนภาพ 320×320 เพื่อฝึกให้ตรงกับขั้นอ่าน crop
- จุดสีดำ น้ำเงิน แดง และเขียว; จุดหลายขนาดและทรงรีเล็กน้อย
- ภาพเอียงประมาณ ±7° มี perspective เล็กน้อย แสงไล่ระดับ noise เบลอ และ JPEG compression
- ภาพไม่มีเบรลล์ เช่น กระดาษ เส้นกรอบ ตัวหนังสือพิมพ์ และวงกลมโปร่ง เพื่อฝึกไม่ให้ตรวจทุกสิ่งเป็นจุด

นี่เป็นภาพสังเคราะห์ของจุดที่แต้มสี ยังไม่ได้จำลองความนูนและแสงเงาของหนังสือจริงครบถ้วน

## 3. Label มาจากไหน และตรวจอะไรแล้ว

ตัวสร้างรู้พิกัดจุดที่วาดตั้งแต่แรก จึงสร้าง label จากเรขาคณิตโดยตรง **ไม่ได้ใช้ CV หรือโมเดลเดิมเดา label** เมื่อหมุน/เอียงภาพ จะใช้การแปลงเดียวกันกับกรอบจุดและตำแหน่งเซลล์

แต่ละภาพมี:

- `images/<split>/*.jpg`: ภาพฝึกที่ไม่มีกรอบ debug ทับ
- `labels/<split>/*.txt`: YOLO label รูปแบบ `class x_center y_center width height` ค่าอยู่ในช่วง 0–1
- `metadata/<split>/*.json`: จุด 1–6, เซลล์, บรรทัด, สัญลักษณ์ต้นทาง และการแปลงภาพ สำหรับตรวจย้อนหลัง

ภาพไม่มีจุดมีไฟล์ label ว่างตามรูปแบบของ YOLO ข้อความใน metadata เป็นข้อมูลประกอบจากรายการคำ/สัญลักษณ์ที่ใช้สร้างภาพ ไม่ได้ถูกใช้เป็น class label และไม่ได้ยืนยันว่าครอบคลุมการเขียนเบรลล์ไทยทุกบริบท

ไฟล์สำคัญในโฟลเดอร์ dataset:

| ไฟล์ | หน้าที่ |
|---|---|
| `data.yaml` | ส่งให้ YOLO ฝึก/ประเมิน |
| `train.txt`, `val.txt`, `test.txt` | รายการภาพของแต่ละชุด |
| `records.jsonl` | กลุ่มฉากต้นทางและ hash ของภาพ/label |
| `dataset.json`, `corpus.json` | รุ่นข้อมูล seed สัดส่วน และรายการรหัสที่ใช้ |
| `validation_report.json` | ผลตรวจ dataset ทั้งหมด |
| `preview.jpg` | ภาพตัวอย่างพร้อมกรอบ label สำหรับตรวจด้วยตา ไม่ใช่ภาพฝึก |

ตรวจครบทุกภาพว่าไฟล์อ่านได้, ขนาดถูก, class ถูก, กล่องไม่ออกนอกภาพ, จำนวน label ตรงกับจุดที่วาด, กล่องตามการหมุนจริง และ hash ไม่เปลี่ยน ไม่พบภาพเหมือนกันทุกไบต์หรือกลุ่มฉากเดียวกันหลุดข้าม split

รหัสไทยอ้างอิงตาราง `config_thai.py` เดิมที่ตรวจเทียบเอกสารมาตรฐานแล้ว ควรตรวจยืนยันกับหนังสือและผู้รู้เมื่อได้ข้อมูลจริง โดยเฉพาะสระผสมและสัญลักษณ์ตามบริบท

## 4. สร้างข้อมูลเพิ่มโดยคงชุดวัดผลเดิม

รอบแรกสร้างเรียบร้อยแล้ว ไม่ต้องรันซ้ำลงโฟลเดอร์เดิม ตัวสร้างจะปฏิเสธการเขียนทับ dataset ที่มีอยู่

ตัวอย่างรอบถัดไป เพิ่มเฉพาะ train อีก 2,400 ภาพ โดยเก็บ train เดิมและใช้ validation/test ชุดเดิม:

```powershell
.venv\Scripts\python.exe tools\training\generate_yolo_training.py --extend-from datasets/thai_synthetic/seed_20260908 --output datasets/thai_synthetic/seed_20260909 --seed 20260909
```

เปลี่ยน seed และชื่อโฟลเดอร์สำหรับแต่ละรอบ `--train-groups` กำหนดจำนวนฉากใหม่ และ `--variants` กำหนดภาพแปรรูปต่อฉาก ค่าเริ่มต้นคือ 1,200 ฉาก × 2 ภาพ การเพิ่มรอบใหม่จะรวมรายการ train เก่าและใหม่ แต่ไม่ทำสำเนาภาพเก่าทั้งหมด

**ทุกภาพแปรรูปของฉากเดียวกันอยู่ split เดียวกันเสมอ** ไม่สุ่มภาพลูกจากฉากเดียวกันไปเป็นทั้ง train และ test และปฏิเสธ seed ที่เคยใช้ในสาย dataset เดียวกัน เพื่อไม่เพิ่มภาพเดิมซ้ำโดยไม่ตั้งใจ

ตรวจข้อมูลซ้ำได้ด้วย:

```powershell
.venv\Scripts\python.exe tools\training\validate_dataset.py datasets/thai_synthetic/seed_20260908
```

รายการภาพในชุดนี้ใช้ absolute path หากย้ายโปรเจกต์หรือส่งไปอีกเครื่อง ให้สร้างรุ่นข้อมูลซ้ำจาก seed/ค่าจำนวนเดิมในตำแหน่งใหม่ หรือปรับ path ในรายการอย่างตรวจสอบได้

## 5. ฝึกต่ออย่างไร

เครื่องที่ตรวจในรอบนี้เป็น PyTorch แบบ CPU ไม่มี CUDA ตัวอย่างเริ่มฝึกชุดหลัก:

```powershell
.venv\Scripts\python.exe tools\training\train_yolo.py --data datasets/thai_synthetic/seed_20260908/data.yaml --epochs 30 --batch 8 --imgsz 640 --device cpu --name thai_synthetic_round1
```

ตัวฝึกตรวจ dataset ก่อน ใช้ weights เดิมจาก `models/braille_yolo.pt` และบันทึกโมเดลทดลองลง `runs/detect/<ชื่อรอบ>/weights/` พร้อมรายงาน `training_report.json` ไม่คัดลอกทับโมเดลหลักอัตโนมัติ และไม่เขียนทับโฟลเดอร์รอบที่มีอยู่

เมื่อมีข้อมูลรอบใหม่ ให้เริ่มรอบฝึกใหม่จาก `best.pt` ของรอบก่อน:

```powershell
.venv\Scripts\python.exe tools\training\train_yolo.py --data datasets/thai_synthetic/seed_20260909/data.yaml --weights runs/detect/thai_synthetic_round1/weights/best.pt --epochs 30 --device cpu --name thai_synthetic_round2
```

`--resume <last.pt>` ใช้เฉพาะการฝึกรอบที่ถูกขัดจังหวะ และต้องใช้ dataset เดิม การฝึกที่จบแล้วให้ใช้ `--weights` เพื่อเปิดรอบใหม่ ไม่ใช้ resume กับชุดข้อมูลรุ่นใหม่

ปิดการพลิกภาพซ้ายขวา/กลับหัวและ mosaic ระหว่างฝึก เพราะข้อมูลสังเคราะห์เตรียมภาพและ label ที่แปลงตรงกันไว้แล้ว ถ้ามี GPU พร้อม PyTorch CUDA จึงเปลี่ยนเป็น `--device 0`

ประเมินการอ่านภาษาไทยของโมเดลทดลองก่อนนำมาใช้:

```powershell
.venv\Scripts\python.exe tools\diagnostics\benchmark_yolo_stream.py --model runs/detect/thai_synthetic_round1/weights/best.pt --output output/candidate_stream_benchmark.json
```

การฝึกจะประเมิน validation ตามรอบอยู่แล้ว เมื่อจะเลือกโมเดลจริงค่อยประเมิน test ที่เก็บไว้:

```powershell
.venv\Scripts\yolo.exe detect val model=runs/detect/thai_synthetic_round1/weights/best.pt data=datasets/thai_synthetic/seed_20260908/data.yaml split=test imgsz=640 device=cpu
```

ทดลองกับกล้องโดยระบุ `--model <ไฟล์ best.pt>` ได้โดยไม่ต้องแทนที่โมเดลหลัก

## 6. ผลตรวจรอบนี้และข้อจำกัด

- ชุดทดสอบปัจจุบันผ่าน **31 tests** รวมความถูกต้องของ marker, แยกบรรทัด, worker, การปฏิเสธโหมด CV, dataset สร้างซ้ำได้, การแยกกลุ่มฉาก, กล่องตรงภาพ, เพิ่ม train โดยไม่เปลี่ยน holdout และการรักษา weights ต้นทาง
- การอ่านด้วย weights หลักยังผ่าน **99/99 ภาพสังเคราะห์มาตรฐาน** หลังถอด CV ออก
- ทดลองฝึกจริง **1 epoch บนชุดเล็ก 40 ภาพ train / 8 ภาพ validation** เพื่อเช็กการเชื่อมต่อข้อมูลและการบันทึก checkpoint ใช้ `scratch/dataset_generator_check/` ผลอยู่ใน `runs/detect/synthetic_smoke_20260908/`
- รอบฝึกสั้นนี้เป็นการตรวจระบบ ไม่ใช่โมเดลที่คัดเลือกมาใช้งาน และไม่ได้ฝึกชุดหลัก 3,000 ภาพครบ 30 epochs
- ตรวจ hash แล้ว weights หลักยังเหมือนก่อนฝึก ไม่มีการสลับโมเดลของกล้อง

ยังไม่ได้เปิดการฝึกยาวหรือการฝึกตามกำหนดเวลาอัตโนมัติ คำสั่งข้างต้นใช้เริ่มแต่ละรอบเมื่อพร้อม คะแนนภาพสังเคราะห์ไม่ใช่ความแม่นยำจากหนังสือจริง เมื่อได้หนังสือให้เพิ่มภาพดิบที่คนตรวจ label แล้ว โดยแยกหน้ากระดาษ/รอบถ่ายก่อนแบ่งชุดข้อมูล และประเมินการตรวจจุดควบคู่ความถูกต้องของข้อความ
