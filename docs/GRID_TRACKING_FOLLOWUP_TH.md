# แก้ Grid หลุดระหว่างถือกล้อง: ผลตรวจจากโค้ดและภาพดิบ

อัปเดต 15 กันยายน 2026 ต่อจาก `GRID_STABILITY_TH.md` บน branch `codex/stable-braille-grid`

## สาเหตุที่ยืนยันได้

1. **ระยะ cell เลือกผิดแล้วสลับคอลัมน์** — `yolo_cell_stream._cell_pitch()` เดิมประเมินว่าคอลัมน์ซ้ายของ cell ที่เห็นครบสองคอลัมน์สามารถเป็นคอลัมน์ขวาของ Grid สมมติได้ ในภาพดิบ frame 2983 ระยะ cell ของบรรทัดสุดท้ายเปลี่ยนจากประมาณ 116 เป็น 78 พิกเซล ทำให้ `[1,2]` กลายเป็น `[4,5]` และเกิดช่องว่างผิด เมื่อแก้สูตรแล้วภาพเดิมอ่านเป็น “นิทานตัว ด” ได้
2. **ใช้ Grid คนละชุดในการอ่านและแสดงผล** — การแก้รอบก่อนทำ smoothing ใน `LivePreview` หลัง decode ส่วน `ColoredCellStream.detect()` ยังอ่านจาก Grid ที่สร้างใหม่ทุกเฟรม การทำให้กรอบบนจอดูนุ่มขึ้นจึงไม่แก้การอ่านผิดจาก geometry
3. **จับคู่ไม่ผ่านแล้วสร้างหมายเลขใหม่ทันที** — `GridStabilizer.update()` เดิมยอมรับ geometry ใหม่ทันทีเมื่อ residual เกินเกณฑ์ ไม่รอยืนยันการเปลี่ยนโครงสร้างจากหลายผลอ่าน จึงเกิดหมายเลข C เพิ่มสูงเมื่อ Grid เปลี่ยน phase
4. **motion ทั้งภาพอาจเป็น motion ของพื้นหลัง** — `estimate_motion()` เดิมหา features ทั่วภาพ ทดสอบสร้างกระดาษเคลื่อนบนพื้นหลังที่มีรายละเอียดสูงและอยู่นิ่งแล้วพบว่า tracker เดิมสามารถเลือก motion ของพื้นหลังได้
5. **แถวเดียวถูกแบ่งเป็นเศษแถว** — bounded clustering อาจแยกแถวที่แต้มสีสูงต่ำไม่เท่ากันเป็นสองกลุ่มที่อยู่ชิดกัน ส่วนการผ่อนเกณฑ์สามแถวรอบก่อนใช้ได้เฉพาะเมื่อทั้งภาพมีสามแถว จึงไม่ครอบคลุมหลายบรรทัด ภาพดิบที่เริ่มอ่านด้วย 47–50 cell บางภาพกลับเป็น 40 cell หลังแก้เงื่อนไขเศษแถว
6. **จุดสีสองจุดเชื่อมกันเป็น component เดียว** — ในภาพดิบของตัว ด พบสอง component พื้นที่ประมาณ 723/743 พิกเซล กลายเป็น component เดียวพื้นที่ 1,543 พิกเซลในอีกเฟรม การใช้ centroid เดียวจึงทำให้จำนวนจุดและผลอ่านเปลี่ยน ไม่ใช่หลักฐานว่าหมึกหายไปจากภาพ

ภาพ diagnostic ที่ตรวจระบุ `candidate_source=color` และ `yolo_inference=false` จึงยืนยันไม่ได้ว่า YOLO bbox เป็นสาเหตุของภาพเหล่านี้ ค่าเริ่มต้น `--roi off` ใช้สีเป็นหลักฐานในการอ่าน ส่วน `--roi yolo` ใช้โมเดลตรวจจุดเสนอ ROI แล้วอ่านเฉพาะสีใน ROI

## โค้ดที่แก้ในรอบนี้

| ไฟล์/ฟังก์ชัน | การแก้และเหตุผล |
|---|---|
| `yolo_cell_stream.py`: `_cell_pitch()` | เพิ่มเงื่อนไขให้คอลัมน์ซ้ายของ cell ที่เห็นครบเป็นตำแหน่งซ้ายของ Grid เสมอ ป้องกันการเลือกระยะย่อยที่ทำให้ sparse cell สลับคอลัมน์ |
| `yolo_cell_stream.py`: `plan_cells()` / `_line_rows()` | รวมเศษแถวเฉพาะเมื่อ median ห่างกันน้อยกว่า 0.35 เท่าของ spacing และช่วงรวมไม่เกิน 0.7 เท่า ไม่ใช้การรวมต่อเนื่องแบบไม่มีขอบเขต แยก text bands ที่ห่างกันชัดเจนก่อน fit สามแถวของแต่ละบรรทัด |
| `cell_tracking.py` | เพิ่ม `CellGridTracker` จับคู่ geometry ก่อนอ่าน โดยชดเชย motion ก่อนลด residual jitter รักษา line/cell order และ track ID ของเซลล์ที่ยังติดตามได้ |
| `cell_tracking.py`: `split_joined_dots()` | แยกก้อนสีเป็นสองจุดเฉพาะเมื่อมีสองตำแหน่งบน Grid ที่มีพิกเซลสีรองรับ และมีบริเวณสีเบาบางคั่นระหว่างสองจุด ปื้นสีทึบและจุดไม่มีสีไม่ผ่านเงื่อนไขนี้ |
| `colored_braille.py` | เส้นทางกล้องส่ง context ให้ tracker ก่อน `read_cell()` เก็บ mask สีของเฟรมปัจจุบันสำหรับตรวจ component ที่เชื่อมกัน เส้นทางอ่านภาพเดี่ยวยังไม่มี state ข้ามภาพ |
| `colored_roi.py` | ตรวจสีใน crop แล้วใช้พิกัดเต็มภาพสำหรับ geometry/recognition ป้องกัน ROI ที่ขยับเปลี่ยนจุดอ้างอิงของ tracker และจำกัด features ของ ROI tracking ให้อยู่ใน ROI |
| `frame_motion.py` | เพิ่ม mask จำกัด features และการตรวจพิกเซลให้อยู่บริเวณ Braille แทนพื้นโต๊ะ ทั้งยังคงการตรวจ forward/backward flow, inliers, scale, angle และ scene loss เดิม |
| `live_preview.py` | ใช้ Grid ชุดที่ recognition ใช้โดยตรง ไม่ smoothing ซ้ำ และชดเชยจากเฟรมที่อ่านไปยังเฟรมที่กำลังแสดงด้วย motion เฉพาะบริเวณ Braille |
| `camera_reader.py` | ส่ง `grid_pending` เป็นสถานะ uncertain จึงไม่ยืนยันข้อความระหว่าง layout เปลี่ยน เพิ่มข้อมูล tracking ใน diagnostic และแก้คำอธิบาย `--stability` ให้ตรงกับการยืนยันข้อความ |
| `yolo_detector.py` | ส่ง camera context เข้าตัวอ่านสี |
| `tests/test_cell_tracking.py` | เพิ่ม 19 tests สำหรับ pitch, แถวแตก, กล้องนิ่ง, translation/rotation, พื้นหลังอยู่นิ่ง, proposal ผิดสองเฟรม, ROI refresh, cell หาย/กลับมา, component เชื่อมกัน, ปื้นสี, current evidence, pending และ scene/context reset |

ไฟล์ launcher, `grid_stability.py` และ tests ของรอบก่อนยังคงอยู่ การแก้ส่วนหัว/ข้อความ console ที่มีอยู่ใน working tree จากภายนอกไม่ได้ถูกย้อนกลับ

## Pipeline ใหม่

`Camera/เฟรมล่าสุด → YOLO ROI ถ้าเปิดใช้งาน → วัดจุดสี → เสนอ Grid → ติดตาม motion ของ Braille → จับคู่และตรวจ geometry → อ่านสีจริงตาม Grid ที่ติดตาม → decode → ยืนยันผลใหม่ตรงกัน → แสดงผล`

- การเคลื่อนจริงตาม optical flow ถูกนำมาใช้ก่อน smoothing เพื่อไม่ให้ Grid ลากตามหลังวัตถุ ลดเฉพาะความคลาดของ proposal ที่เหลือด้วยน้ำหนัก geometry ที่ติดตาม 75% / ค่าที่วัดใหม่ 25%
- Proposal ที่เปลี่ยน phase แต่พิกเซลปัจจุบันยังรองรับ Grid เดิมไม่ทำให้ Grid กระโดด หากหลักฐานบ่งชี้ว่า layout เปลี่ยน ต้องได้ proposal ที่สอดคล้องกันสามผลใหม่ก่อนรับ layout ใหม่
- รักษา geometry ของ cell ที่หายชั่วคราวระหว่างยืนยัน แต่ **ไม่วาดหรือ decode cell ที่ไม่มีหลักฐานสีปัจจุบัน** เมื่อกลับมาภายในสองผลอ่านยังใช้ ID เดิมได้
- ไม่เก็บ dot pattern เก่ามาเติมเฟรมใหม่ การแยก component ที่เชื่อมกันใช้พิกเซลสีของเฟรมปัจจุบันเท่านั้น
- ล้าง state เมื่อสี/ภาษา/context/ขนาดภาพเปลี่ยน ไม่มีจุดสี ติดตาม motion ไม่ได้ หรือผลขาดช่วงเกิน 0.75 วินาที
- ข้อความยังต้องตรงกันครบ 6 ผลอ่านใหม่ ค่าเดิม ไม่ได้นับ UI tick ซ้ำ การเปลี่ยน layout ที่กำลังยืนยัน ภาพอ่านไม่ได้ และ scan error ไม่ผ่านการยืนยัน
- Camera และ worker ยังใช้ latest-frame queue และเจ้าของ resource เดิม ไม่มีการเปิด/ปิดกล้องใหม่ตาม scan error และไม่มีการเพิ่ม inference queue
- TTS ใน implementation ปัจจุบันยังถูกเรียกจาก image CLI `main.py --speak` ไม่ได้เชื่อม auto-TTS ใน camera loop งานนี้ไม่ได้เพิ่มระบบเสียง หากต่อภายหลังควรใช้เหตุการณ์ข้อความยืนยันใหม่พร้อมป้องกันพูดซ้ำ

## ผลทดสอบ

- Unit/regression suite: **129 tests ผ่าน** รวม camera recovery, สี, ไทยสองเซลล์, หลายบรรทัด และ tests ใหม่ 19 รายการ
- YOLO stream benchmark ด้วย weights จริง: **99/99 ผ่าน**
- Camera CLI `--help` และ `git diff --check` ผ่าน ไม่มี dependency ใหม่
- ตรวจภาพดิบและ manifest จากกล้อง รวมทั้งชุดที่บันทึกเพิ่มระหว่างทำงาน ไม่ใช้ screenshot ที่มี overlay เป็น input ทดสอบ recognition
- เฟรมจริง 2983 ที่มี pitch ผิด อ่านกลับเป็นข้อความเดียวกับเฟรมคมของหนังสือได้
- เมื่อมี Grid อ้างอิงที่ถูกต้อง การแยก component ที่เชื่อมกันช่วยให้เฟรมจริง 3209/3248 อ่านตัว ด ได้ ส่วนภาพที่เริ่มต้นด้วย component ที่รวมกันและยังไม่มี Grid อ้างอิงที่ถูกต้องอาจยังอ่านไม่ได้ ต้องรอเฟรมใหม่
- Diagnostic กล้องชุด `178939870...` ที่บันทึกก่อนการปรับแยก component/เศษแถวครั้งสุดท้ายมี 40 cell / 3 บรรทัดครบทั้ง 18 ไฟล์ โดยเฟรมที่หลักฐานเปลี่ยนถูกระบุ pending หลายไฟล์เป็น frame เดียวกัน จึงไม่นับเป็นหลักฐานยืนยันเพิ่ม

Benchmark ด้านล่างใช้ภาพดิบหนังสือจริงสร้างการเลื่อน/หมุนที่ทราบค่า 32 เฟรมต่อกรณี ตัด warm-up ห้าเฟรม วัด read + decode + preview แบบเรียงลำดับ ไม่มี capture, queue wait หรือเสียง ค่า RMSE เป็นค่าเฉลี่ยความคลาดของ slots จากตำแหน่งที่คาดตาม motion ในพิกเซลภาพต้นฉบับ **ไม่ใช่ความแม่นยำภาษาไทยบน dataset ทั้งหมด และไม่ใช่ FPS กล้องสด**

| ตัวชี้วัด | ก่อนรอบนี้ | หลังรอบนี้ |
|---|---:|---:|
| FHD Grid RMSE | 0.289 px | 0.231 px |
| 4K Grid RMSE | 4.056 px | 0.271 px |
| FHD: จำนวนครั้งที่รายการ track IDs เปลี่ยน | 2 ครั้ง | 0 |
| 4K: จำนวนครั้งที่รายการ track IDs เปลี่ยน | 3 ครั้ง | 0 |
| FHD / 4K: ข้อความเปลี่ยนใน replay | 2 / 3 ครั้ง | 0 / 0 |
| FHD read + preview median | 46.81 ms | 52.72 ms |
| FHD read + preview p95 | 47.99 ms | 55.78 ms |
| 4K read + preview median | 71.07 ms | 77.01 ms |
| 4K read + preview p95 | 75.59 ms | 80.94 ms |

ต้นทุนเพิ่มประมาณ 6 ms ต่อรอบในชุดนี้ แลกกับการตรวจ geometry และหลักฐานสีเพิ่ม จึงไม่อ้างว่าเร็วขึ้น ความเร็วจริงขึ้นกับ CPU, resolution, จำนวน cell และโหลดเครื่อง โค้ด tracking เก็บเพียง geometry ปัจจุบัน/pending และภาพเทาระดับไม่เกิน 640 พิกเซลด้านกว้าง ไม่สะสมวิดีโอ

ไฟล์ทำซ้ำและผลดิบอยู่ใน `scratch/motion_review/benchmark.py`, `timing.json`, `audit.py`, `before.jsonl`, `after.jsonl`, `yolo_regression.json` โดยโฟลเดอร์ scratch ถูก ignore ตัว benchmark ใช้ `5c6b23c` พร้อมการแก้รอบก่อนเพื่อสร้าง baseline เส้นทางอ่าน/แสดงผล

## ข้อจำกัดและวิธีทดสอบต่อ

- การจับครั้งแรกยังต้องเห็น geometry ที่พอแยกแถวและคอลัมน์ได้ เมื่อเคลื่อนเร็ว เปลี่ยนหน้าหรือบังจน flow ใช้ไม่ได้ ระบบจะจับใหม่ ไม่ตรึง Grid เก่าไว้บนฉากใหม่
- ภาพ diagnostic เป็นภาพที่เลือกบันทึกและมีช่วงห่าง ไม่ใช่วิดีโอต่อเนื่อง การ replay ต้องไม่นับไฟล์ซ้ำเป็นเฟรมใหม่และต้อง reset เมื่อช่วงห่างเกินเกณฑ์ ผลดังกล่าวใช้แทนการทดสอบ live ทุกมุม/ทุกแสงไม่ได้
- ยังมีภาพจากหน้า/บริเวณอื่นที่ geometry กำกวมและถูกระบุ pending/uncertain จึงยังไม่รับรองการอ่านทุกบรรทัดของหนังสือ การทดสอบนี้ยืนยันการแก้ pitch, row fragmentation และการติดตามหลังจับ Grid ได้แล้ว ไม่ใช่การรับรองความแม่นยำทั้งเล่ม
- เริ่มที่ FHD เพื่อเทียบ latency และความนิ่ง หากจุดเล็กจนรายละเอียดไม่พอให้ใช้ 4K ถือให้เห็นแถวจุดครบช่วงเริ่มต้น ล็อก exposure/focus ถ้ากล้องรองรับ และหลีกเลี่ยงการแต้มหมึกเชื่อมสองจุด

```powershell
.venv\Scripts\python.exe camera_reader.py --lang thai --res fhd --dot-color blue --sharp 0
```

กด `C` สลับน้ำเงิน/แดง และ `D` เก็บ diagnostic หากต้องการทดสอบ YOLO ROI ให้เพิ่ม `--roi yolo` เปิดโปรแกรมใหม่ด้วยโค้ดล่าสุดก่อนเปรียบเทียบ เพราะโปรเซสที่เปิดอยู่แล้วอาจยังใช้โมดูลเวอร์ชันก่อนหน้า
