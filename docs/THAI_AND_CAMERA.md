# ภาษาไทย 2 เซลล์ สระวรรณยุกต์ และการแสดงภาพกล้อง

ปรับบน branch `feature/yolo-detection` วันที่ 7 กันยายน 2026

เอกสารนี้บันทึกการแก้ CV/Hybrid รอบก่อน สำหรับ branch YOLO แยกบรรทัดและอ่าน crop ดู [YOLO_CELL_STREAM.md](YOLO_CELL_STREAM.md)

## สาเหตุที่ตรวจพบ

1. **CV จัดคอลัมน์ผิด:** ภาพที่เริ่มด้วย ญ ศ ภ มีจุดนำ `{6}` อยู่ทางขวาล่าง แต่โค้ดเดิมสมมุติว่าคอลัมน์แรกที่พบเป็นคอลัมน์ซ้าย ทำให้ได้ `{3}` ตัว decoder เมื่อรับจุดที่ถูกต้องอ่านพยัญชนะเหล่านี้ได้อยู่แล้ว แก้โดยอ้างอิงตำแหน่งคอลัมน์จากเซลล์ถัดไป รวมกรณี ฬ ที่เซลล์ตามมีคอลัมน์เดียว
2. **ตารางเก่ามีรหัสต่างจากมาตรฐาน:** ตารางใหม่แก้ อึ=246, อื=26; วรรณยุกต์ เอก=35 โท=256 ตรี=2356 จัตวา=236 และรหัสสระผสม เก็บตารางเก่าใน `config_thai_legacy.py` สำหรับทดสอบภาพสังเคราะห์เดิมเท่านั้น
3. **ป้ายกำกับเป็นรายเซลล์:** เดิมข้อความเต็มกับป้ายบนภาพใช้คนละตรรกะ จึงอาจแสดง prefix เป็นเครื่องหมายคนละตัว ปัจจุบัน tokenizer เก็บช่วงเซลล์ที่ประกอบเป็นตัวเดียว ป้าย ญ/ศ/ภ/ธ แสดงครั้งเดียวและมี `cell_start`/`cell_end` สำหรับตรวจสอบ
4. **สระผสมและวรรณยุกต์:** แยกการอ่าน token ออกจากการประกอบข้อความ รองรับสระผสมที่อยู่หลังพยัญชนะและวรรณยุกต์ก่อน/หลังสระผสม การ normalize ใหม่จัดลำดับเครื่องหมายเท่านั้น ไม่เปลี่ยนสระที่อ่านได้เป็นวรรณยุกต์ด้วยการเดาคำ

ไม่ควรเทรน YOLO เพื่อแก้รหัสภาษา: โมเดลปัจจุบันตรวจ **จุด** การจัดเซลล์และการรวมตัวอักษรเป็นหน้าที่ของ CV/decoder ควรเพิ่มข้อมูลและเทรนเมื่อภาพจริงแสดงว่าจุดขาด จุดเกิน หรือระบุตำแหน่งผิด

## ข้อมูลอ้างอิงและขอบเขต

- Liblouis, Thai uncontracted table `th-g0.utb`: https://raw.githubusercontent.com/liblouis/liblouis/master/tables/th-g0.utb
- World Braille Usage, third edition (2013), หน้าที่พิมพ์ 140–141: https://www.perkins.org/wp-content/uploads/2021/07/world-braille-usage-third-edition.pdf

ตารางใหม่นี้ยังไม่ใช่ตัวแปลภาษาไทยครบทุกบริบท สัญลักษณ์ การันต์ `{356}` กับ prefix ของ ธ/ฃ ยังอาจกำกวมเมื่อมีพยัญชนะตามต่อเนื่อง จึงรายงาน `ambiguous_prefix_or_karan` ในรายละเอียด token และใช้การจับคู่เซลล์ตามตาราง ยังไม่ได้เพิ่มพจนานุกรมเพื่อเดาคำ กรณีสระผสมที่ไม่มีพยัญชนะต้นให้จับคู่หรือ prefix ไม่ครบจะแสดง `�` แทนการเติมตัวอักษรที่ไม่ได้เห็น

ควรให้อาจารย์หรือผู้ใช้อักษรเบรลล์ไทยตรวจชุดคำอ้างอิงก่อนนำไปสร้าง dataset ขนาดใหญ่ โดยเฉพาะการันต์ พยางค์ต่อเนื่อง เครื่องหมายพิเศษ และสระรูปย่อ

## สิ่งที่ปรับกับกล้อง

- แคชกรอบและข้อความเมื่อผล AI ยังเป็นรายการเดิม จึงไม่ต้องวาดด้วย PIL ใหม่ทุกเฟรม
- ลดขนาดเฉพาะภาพแสดงผลเป็นความกว้างสูงสุด 1280 พิกเซล และแปลงพิกัดกริดให้ตรงกัน
- AI รับภาพต้นฉบับหรือ crop ที่ความละเอียดจริง ไม่ขยายพิกเซลหลังซูม
- เพิ่มความคมเฉพาะเฟรมที่ worker รับไปประมวลผล ไม่ทำงาน 4K ซ้ำในลูปหน้าจอ
- ส่งภาพใหม่ให้ AI ตามเลขเฟรมของกล้อง และเก็บเฉพาะภาพล่าสุด
- CV ที่ใช้ภายใน Hybrid ไม่วาดภาพ debug ที่ไม่ได้ใช้ และ HUD ผสมสีเฉพาะแถบด้านบน

ผลเปรียบเทียบ headless บนเครื่องพัฒนา (20 รอบหลัง warm-up ภาพ 3840×2160 มีข้อความและไม่มีจุด) อยู่ใน `output/preview_benchmark.json`: วาดเต็มภาพมัธยฐานประมาณ 37.6 ms เทียบกับ preview/overlay ที่แคชประมาณ 2.0 ms ตัวเลขนี้วัดเฉพาะงานวาด ไม่ใช่ FPS กล้องหรือ YOLO และไม่ใช่ผลบน Redxa

## การทดสอบและ dataset

- 29 กรณีรหัสอ้างอิงที่กำหนดชุดจุดโดยตรง แยกจาก reverse mapping ของ config
- ตรวจรหัสอ้างอิงทั้ง decoder และภาพที่ย่อเหลือ 25% / 20% รวม 87 กรณีภาพ
- ทดสอบกลุ่มพยัญชนะ 2 เซลล์ สระวรรณยุกต์ คำผสม การไม่จับ prefix ข้ามบรรทัด/ช่องว่าง และการไม่เปลี่ยนสระเป็นวรรณยุกต์จากการเดา
- รายงานโมเดลจริงในโหมด **Hybrid**: `output/standard_thai_benchmark.json` ผ่าน 87/87 กรณี ไม่ใช่ผล YOLO stream
- ภาพเก่าแยกทดสอบด้วย `thai-legacy`; คะแนนเหล่านี้เป็น regression ของภาพเดิม

ภาพสังเคราะห์ยังไม่ใช่ชุดทดสอบจากกล้องจริง ควรเก็บกระดาษจริงหลายแผ่น แสง ระยะ มุม และขนาดจุด กำกับจุดและข้อความด้วยคน แยก train/validation/test ตามแผ่นกระดาษหรือรอบถ่าย และค่อยเพิ่ม augmentation ภายใน train ห้ามแยกภาพลูกจากต้นฉบับเดียวกันไปคนละชุด

## จัดไฟล์

ย้าย unit tests ไป `tests/`, เครื่องมือฝึกไป `tools/training/`, เครื่องมือวิเคราะห์ไป `tools/diagnostics/` และสคริปต์ตรวจรุ่นเก่าไป `archive/legacy_checks/` ภาพที่วาดกรอบ YOLO แล้วอยู่ใน `output/legacy_previews/` เพื่อไม่ปะปนกับภาพต้นฉบับ โมเดล ข้อมูลฝึก ภาพดิบ และ environment เดิมยังอยู่ครบ
