# ระบบอ่านเบรลล์ตามปลายนิ้ว — Design

วันที่: 2026-10-21
Branch: `codex/mediapipe-hand-tracking-spike`

## เป้าหมาย

ผู้พิการทางสายตาเลื่อนนิ้วบนบรรทัดเบรลล์นูน ระบบออกเสียงชื่อสัญลักษณ์ของเซลล์ใต้นิ้ว และออกเสียงคำเต็มเมื่ออ่านจบคำ

ตัวอย่างคำว่า `ไก่`:

```text
ปลายนิ้วผ่าน:  ไ          ก        ่          ช่องว่าง
เสียง:         "สระไอ"   "กอไก่"  "ไม้เอก"  "ไก่"
```

เกณฑ์สำเร็จ:

- ทำงาน real-time ด้วยกล้องติดขาตั้ง สูงประมาณ 20 cm
- อ่านเซลล์ถูกอย่างน้อย 90% ในสภาพแสงควบคุม (แสงทั่วหน้า)
- เสียงเริ่มภายใน 0.3–0.5 วินาทีหลังปลายนิ้วเข้าเซลล์ใหม่

## ข้อตกลงด้านหนังสือ

| หัวข้อ | ข้อตกลง |
|---|---|
| ผู้ทำหน้า | ทีมออกแบบใน Microsoft Word จาก template ของเรา |
| ขนาด | A5 แนวนอน (210 × 148 mm) ตั้ง Word เป็น A4 แนวตั้ง พิมพ์แบบ No Scaling แล้วตัดครึ่ง ได้ 2 หน้าต่อแผ่น |
| กล้องเห็น | ครั้งละ 1 หน้า (พับสมุดสันห่วงให้เหลือหน้าเดียว) |
| บรรทัดสี | ฟอนต์ `SOV_braille_only` ขนาด 30 สีน้ำเงิน ชิดซ้าย |
| บรรทัดนูน | ทำด้วยสเลทในบรรทัดว่างใต้บรรทัดสี ทุกเซลล์ตรงกับเซลล์สีแบบ 1:1 |
| จำนวนคู่บรรทัด | 3–4 คู่ต่อหน้า (บรรทัดสี บรรทัดนูน สลับกัน) ประมาณ 24 เซลล์ต่อบรรทัด |
| marker | ArUco `DICT_4X4_50` ID 0–3 (TL, TR, BR, BL) ขนาด 1.5 cm ห่างขอบหน้า A5 และเส้นตัด 1.0 cm วางใน Header ของ Word รวม 8 ตัวต่อแผ่น A4 (ID 0–3 ซ้ำทั้งครึ่งบนและครึ่งล่าง) |
| การจัดสเลท | พิมพ์สองหน้า ด้านหลังมีขีดนำสีเทาอ่อนบอกจุดเริ่มของแต่ละบรรทัดนูน |

ขนาดฟอนต์ (วัดจากไฟล์ `SOV_braille_only.ttf`):

- ระยะจุด = 0.22 × ขนาดฟอนต์ (pt)
- ระยะเซลล์ = 0.54 × ขนาดฟอนต์ + Expanded (pt)
- ค่าปัจจุบัน 30 pt + Expanded 1.4 pt ได้ระยะจุด 2.33 mm และระยะเซลล์ 6.21 mm

ระยะเซลล์และระยะบรรทัดต้องตรงกับสเลท:

- Expanded (pt) = ระยะเซลล์ของสเลท (mm) ÷ 0.3528 − 16.2
- Line spacing แบบ Exactly (pt) = ระยะบรรทัดของสเลท (mm) ÷ 0.3528

ความคลาดเคลื่อนที่รับได้: เซลล์นูนคลาดจากเซลล์สีแนวนอนไม่เกินประมาณ 2.5 mm และบรรทัดนูนต้องไม่ทับบรรทัดสี

## แนวทางที่เลือก

โปรแกรมใหม่ `finger_reader.py` แยกจากโหมดสแกนเดิม ทำงาน 2 ช่วง:

1. **จดจำหน้า** — ตอนไม่มีมือในภาพ calibrate หน้า อ่านบรรทัดสีทั้งหน้าครั้งเดียว และสร้างเสียงล่วงหน้า
2. **อ่านตามนิ้ว** — ทุกเฟรมตรวจแค่ปลายนิ้ว แปลงเป็นเซลล์จากแผนที่หน้า แล้วเล่นเสียง

ทางเลือกที่ไม่เลือก:

- รวมเป็นโหมดใน `camera_reader.py` — ไฟล์ยาวเกิน 1,300 บรรทัด และเสี่ยงทำให้โหมดสแกนเดิมพัง
- อ่านบรรทัดสีใหม่ทุกเฟรม — ช้า (~4 fps) และมือบังบรรทัดสี
- พิมพ์อักษรไทยแทนเบรลล์สี — ต้องทำ OCR ประมาณ 70 แบบที่หลายตัวคล้ายกัน และอักษรไทยกับเซลล์เบรลล์ไม่ตรงกัน 1:1 เสมอ
- ใช้รหัสหน้าแทนการอ่าน — แม่น แต่ไม่ได้อ่านเบรลล์

## โครงสร้าง

```text
finger_reader.py  (โปรแกรมหลัก)
 ├─ page_calibration.py  (มีแล้ว แก้) A5 แนวนอน, marker 1.5 cm ห่างขอบ 1.0 cm, เก็บ calibration ล่าสุด
 ├─ page_map.py          (ใหม่) อ่านบรรทัดสีจากภาพที่แก้เอียงแล้ว → PageMap
 ├─ fingertip.py         (ใหม่) ย้ายการตรวจนิ้วและ ActiveFingertipLock จาก spike
 ├─ finger_state.py      (ใหม่) state machine → เหตุการณ์ enter_cell / finish_word
 └─ speech_queue.py      (ใหม่) cache เสียง + คิวที่ตัดเสียงเก่า ใช้ Piper/MMS ที่มีอยู่
```

| โมดูล | รับ | คืน | พึ่งพา |
|---|---|---|---|
| `page_calibration` | ภาพ | สูตรแปลง px ↔ mm หรือสถานะล้มเหลวพร้อมเหตุผล | OpenCV ArUco |
| `page_map` | ภาพหน้าที่แก้เอียงแล้ว (8 px/mm) | `PageMap`: แต่ละคู่บรรทัดมีช่วง y ของบรรทัดนูน และรายการเซลล์ (ช่วง x mm, จุด, ชื่อสัญลักษณ์, ดัชนีคำ) และรายการคำ | `colored_braille`, decoder, `thai_speech` |
| `fingertip` | ภาพ | ปลายนิ้วที่ล็อกแล้ว (px) หรือ `None` | MediaPipe Hand Landmarker |
| `finger_state` | ตำแหน่งนิ้ว (mm), `PageMap`, เวลา | รายการเหตุการณ์ | ไม่มี (logic ล้วน) |
| `speech_queue` | เหตุการณ์ | เล่นเสียง | `piper_tts` / MMS |

หลักการ:

- `finger_state` ไม่ใช้กล้องและเสียง จึงทดสอบครบทุกกรณีได้
- `page_map` อ่านในภาพที่แก้เอียงแล้วและรู้สเกล ระยะจุดและระยะเซลล์ตั้งเป็นค่าใน `PageFormat` จากการวัดหน้าตัวอย่าง
- ตำแหน่งเซลล์ในแนวนอนใช้ของเซลล์สี แล้วลากลงไปที่บรรทัดนูน ไม่ต้องตรวจจุดนูน
- ตำแหน่งนิ้วแปลงเป็น mm ด้วยสูตรเดียวกับหน้า จึงไม่ขึ้นกับมุมกล้อง
- `tools/diagnostics/hand_landmarker_spike.py` เปลี่ยนไปเรียกใช้ `fingertip.py`

ไม่ทำในรอบนี้: โหมดกาง 2 หน้า, การรวมกับ UI โหมดสแกนเดิม, หน้าที่ไม่มี marker, UI ที่สวยงาม (มีแค่พรีวิวสำหรับ debug)

## ลำดับการทำงาน

```text
           ┌──────────── marker ขยับเกิน 3 mm / หายเกิน 2 วินาที ────────────┐
           ▼                                                                │
[รอหน้า] ──เห็น marker ครบ 4──▶ [จดจำหน้า] ──แผนที่นิ่ง──▶ [อ่านตามนิ้ว] ──┘
           ▲                        │
           └── ไม่มี marker ─────────┘ (พูด "วางหน้าให้เห็นมุมครบ")
```

### จดจำหน้า

1. ต้องไม่มีมือในภาพ ถ้ามีมือ พูด "ยกมือออกก่อน" ครั้งเดียว แล้วรอ
2. calibrate แล้วแก้ภาพหน้าให้ตรงที่ 8 px/mm
3. `page_map` อ่านบรรทัดสีทั้งหน้า
4. ทำซ้ำจนได้ผลตรงกัน 3 เฟรมติดกัน แผนที่หน้าจึงนิ่ง
5. เซลล์ที่อ่านไม่ออกให้ทำเครื่องหมายไว้ เมื่อนิ้วเข้าเซลล์นั้นพูด "ไม่ทราบ" ห้ามเดา
6. สร้างเสียงของทุกคำในหน้า (ชื่อสัญลักษณ์มี cache ถาวร) แล้วพูด "พร้อม N บรรทัด"

### อ่านตามนิ้ว (ทุกเฟรม)

1. `fingertip` ตรวจปลายนิ้วชี้หรือนิ้วกลาง แล้วแปลงเป็น mm ด้วย calibration ล่าสุด
2. ถ้านิ้วอยู่ในช่วง y ของบรรทัดนูนคู่ใด ให้หาเซลล์ที่ช่วง x ครอบตำแหน่งนิ้ว
3. `finger_state`:
   - `outside → candidate(c)` เมื่อนิ้วเข้าเซลล์ c
   - `candidate(c) → active(c)` เมื่ออยู่ในเซลล์ c นาน 0.15 วินาที แล้วส่ง `enter_cell(c)`
   - ส่ง `finish_word(w)` เมื่อนิ้วออกจากคำ w ไปทางขวา คือเข้าเซลล์ว่างหลังคำ หรือเลยท้ายบรรทัด
   - ขอบเซลล์มี hysteresis 0.5 mm
4. `speech_queue` ตัดเสียงที่กำลังเล่น แล้วเล่นเสียงใหม่ทันที

### กรณีผิดพลาด

| เหตุการณ์ | ระบบทำอะไร |
|---|---|
| มือบัง marker บางตัว | ใช้ calibration ล่าสุดต่อไป |
| marker หายหมดเกิน 2 วินาที หรือขยับเกิน 3 mm | กลับไปจดจำหน้าใหม่ |
| ไม่เจอนิ้ว หรือนิ้วอยู่นอกบรรทัดนูน | สถานะ `outside` ไม่พูด |
| นิ้วเลื่อนย้อนกลับ | พูดชื่อสัญลักษณ์ของเซลล์ที่เข้าใหม่ ไม่พูดคำเต็ม |
| นิ้วข้ามเซลล์เร็ว | พูดเฉพาะเซลล์ปัจจุบัน |
| เสียงคำยังไม่พร้อม | พูดตัวสะกดทีละสัญลักษณ์แทน และบันทึก log |
| สร้างเสียงไม่ได้ (ไม่มีโมเดล) | แจ้ง error ตอนเริ่มโปรแกรม |

ค่าที่ปรับได้ (ใน `PageFormat` / config): dwell 0.15 วินาที, hysteresis 0.5 mm, จำนวนเฟรมให้แผนที่นิ่ง 3, เกณฑ์ marker ขยับ 3 mm, เวลาที่ marker หายได้ 2 วินาที

## การทดสอบ

### Unit test (ไม่ใช้กล้อง)

| โมดูล | กรณีทดสอบ |
|---|---|
| `finger_state` | ไ → ก → ่ → ช่องว่าง ได้ "สระไอ" "กอไก่" "ไม้เอก" "ไก่" / dwell ไม่ถึง 0.15 วินาทีไม่พูด / ย้อนกลับไม่พูดคำเต็ม / ข้ามเซลล์พูดแค่เซลล์ปัจจุบัน / นิ้วสั่นบนขอบไม่พูดสลับ / นิ้วหายกลับเป็น `outside` |
| `page_map` | หน้าสังเคราะห์จาก `render_page` (A5 แนวนอน 3 คู่บรรทัด) แบบตรงและแบบเอียง ได้เซลล์และจุดครบ / เซลล์ที่จุดหายถูกทำเครื่องหมายอ่านไม่ออก |
| `page_calibration` | test เดิม + A5 แนวนอน + marker ถูกบังบางตัวใช้ค่าล่าสุด + marker ขยับเกิน 3 mm สั่งจดจำใหม่ |
| `speech_queue` | TTS ปลอม: เหตุการณ์ใหม่ตัดเสียงเก่า / เสียงคำไม่พร้อมพูดตัวสะกดแทน |
| `fingertip` | test ของ spike ย้ายตามโมดูล |

### ทดสอบกับของจริง

1. **ความแม่นยำ ≥90%** — `tools/diagnostics/page_map_accuracy.py` อ่านหน้าจากกล้องแล้วเทียบกับไฟล์เฉลยทีละเซลล์ ทำ 3 หน้า × 3 สภาพแสง (แสงทั่ว / แสงข้างเดียว / แสงห้องปกติ) เป้า 90% ใช้กับแสงทั่ว สภาพแสงอื่นบันทึกเป็นข้อจำกัด
2. **เวลาเริ่มเสียง** — `finger_reader.py --log-latency` บันทึกเวลาแต่ละขั้น (ได้ภาพ → ตรวจนิ้ว → เข้าเซลล์ → active → เริ่มเล่นเสียง) ไล่นิ้ว 20 ครั้ง รายงาน median และ p90 ส่วนความหน่วงของกล้องเองวัดจาก log ไม่ได้ (ประมาณไม่เกิน 33 ms ที่ 30 fps)
3. **ใช้งานจริง** — ให้คนอ่านคำว่า `ไก่` และประโยคสั้น 3 ประโยค จดเสียงที่ผิดหรือพูดซ้ำ

## ลำดับการพัฒนา

แต่ละขั้นต้องมี test ผ่านก่อนไปขั้นถัดไป

1. แก้ `PageFormat` เป็น A5 แนวนอน 3–4 คู่บรรทัด, สร้างไฟล์ marker PNG และ template Word A4 แนวตั้งแบบพิมพ์สองหน้า (ครึ่งบนและครึ่งล่างเป็นหน้า A5 ด้านหลังมีขีดนำ)
2. `finger_state`
3. `page_map`
4. `fingertip` (ย้ายจาก spike)
5. `speech_queue`
6. `finger_reader.py` ต่อทุกส่วน แล้วทดสอบกับกล้องจริง

## สิ่งที่ต้องได้จากทีม

ก่อนขั้น 1 (template):

- ระยะเซลล์ของสเลท (วัด 10 เซลล์) ระยะบรรทัดของสเลท และจำนวนช่องต่อแถว

ก่อนขั้น 3 (`page_map`):

- หน้าตัวอย่างที่พิมพ์จริง 1 หน้า พร้อม marker
- ขนาด marker ที่วัดได้บนกระดาษจริง (ตรวจว่าการพิมพ์ไม่ย่อขนาด)
- ข้อความเฉลยของหน้านั้น
