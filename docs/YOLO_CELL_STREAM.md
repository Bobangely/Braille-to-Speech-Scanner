# YOLO: อ่านทีละเซลล์ แล้วประกอบเป็นข้อความ

พัฒนาบน `codex/yolo-cell-stream` แยกจาก `feature/yolo-detection` โดยใช้ weights เดิมใน `models/braille_yolo.pt`

อัปเดต: ถอด CV/Hybrid และโหมด `legacy` ออกจากเส้นทางใช้งานแล้ว เหลือ YOLO cell stream เท่านั้น ดู [dataset และวิธีฝึกต่อ](SYNTHETIC_DATASET.md)

รีวิวก่อน merge ล่าสุดเพิ่มการตรวจแถวที่กำกวม การแสดงเซลล์ที่อ่านไม่สำเร็จ และการตรวจข้อมูลฝึก ดู [รายละเอียดและข้อจำกัด](PRE_MERGE_REVIEW_TH.md)

## สิ่งที่แก้

- จัดบรรทัดก่อนสร้างเซลล์ และตัดขอบ crop ที่กึ่งกลางระหว่างบรรทัด/คอลัมน์ข้างเคียง จุดหนึ่งมีเจ้าของเพียงเซลล์เดียว
- อ่าน crop ทีละเซลล์ด้วย YOLO เป็นชุดย่อย แล้วส่งออกตามลำดับบรรทัดและซ้ายไปขวา
- จับ marker กับเซลล์ถัดไปตาม `THAI_MULTI_CELL` เช่น `6 + 13456 → ญ`, `6 + 234 → ศ`, `6 + 1456 → ภ`, `356 + 23456 → ธ`
- ใช้ระยะเซลล์ที่ประมาณจากภาพ (`cell_pitch`) และตำแหน่งหลังปรับแนว (`reading_x`) แทนระยะตายตัวในการจับคู่
- การประกอบคำรักษา `line_id` เป็นการขึ้นบรรทัดใหม่ และไม่จับ marker ข้ามบรรทัดหรือช่องว่างระหว่างคำ
- ลดกรอบตรวจจับซ้ำบนจุดเล็กด้วย NMS IoU 0.2 และไม่นำระยะระหว่างศูนย์กลางที่อยู่ภายในจุดเดียวกันไปประมาณระยะกริด

## Pipeline ที่ใช้จริง

```text
ภาพต้นฉบับ / ROI กล้อง
  → YOLO ตรวจจุดในภาพรวม และ tiles ตามขนาดภาพ
  → ปรับแนวพิกัด → แยกบรรทัด → เสนอกรอบเซลล์ 2×3
  → crop เฉพาะเซลล์ → YOLO อ่าน crop เป็น batch
  → กำหนดจุด 1–6 → จับคู่ marker + body
  → tokenizer ภาษาไทย → ประกอบสระ/วรรณยุกต์ → ข้อความแยกบรรทัด
```

**โมเดลที่มีอยู่ตรวจ `braille_dot` หนึ่งคลาส ไม่ใช่กรอบตัวอักษรหรือกรอบเซลล์โดยตรง** ดังนั้นกรอบ crop มาจากตำแหน่งจุดของ YOLO และเรขาคณิต ถ้าจะให้ YOLO ทำนายกรอบเซลล์โดยตรง ต้องทำ annotation เซลล์เต็ม 2×3 รวมช่องที่ว่าง และฝึกโมเดลอีกชุดก่อน

โหมด `yolo + stream` ไม่เรียกการตรวจสีหรือรวมจุดจาก Hybrid; OpenCV ใช้สำหรับแปลงภาพ พิกัด และวาดผลเท่านั้น การทดสอบ unit บางรายการใช้ตัวจำลองอ่านจุดสีเพื่อแยกทดสอบเรขาคณิต ส่วน benchmark ใช้ weights YOLO จริงทั้งสองรอบ

ภาพรวมใช้ confidence เริ่มต้น `min(0.30, --conf)` เพื่อเสนอ crop ให้ครอบคลุม ส่วน crop ยืนยันจุดด้วย `--conf` ซึ่งเริ่มต้นที่ 0.35 ถ้า crop อ่านไม่พบจุด จะไม่เติมจุดจากภาพรวมกลับเข้ามา

crop ถูกปรับให้ระยะจุดประมาณ 32 px แล้ววางบนพื้นขาว 320×320 เพื่อรักษาขนาดจุดที่เข้าโมเดล โดยตัดบริบทนอกกรอบออก ใช้ batch เริ่มต้น 8 เซลล์ จำกัดสูงสุด 256 เซลล์ต่อภาพ ถ้าเกินขีดจำกัดจะแจ้งข้อผิดพลาดให้ลดพื้นที่สแกน ไม่ตัดหน้ากระดาษทิ้งเงียบ ๆ

## การแก้ marker 3/6

ไม่เปลี่ยนจุด `3` เป็น `6` ทุกครั้ง แก้เฉพาะเมื่อครบทุกเงื่อนไข:

1. อยู่ต้นบรรทัด (`line_cell_index == 0`)
2. เรขาคณิตยังตัดสินซ้าย/ขวาไม่ชัด (`column_ambiguous`)
3. เซลล์ถัดไปอยู่บรรทัดเดียวกันและใกล้พอ
4. `6 + เซลล์ถัดไป` เป็นสัญลักษณ์ที่มีในตารางจริง

เมื่อแก้ จะปรับกริดแสดงผลและพิกัดประกอบคำให้ตรงกับจุดที่เห็น เก็บ `marker_repair`, `overview_dots`, `read_pattern` และ `crop_quad` เดิมไว้ตรวจย้อนหลัง รหัส `3` ที่ไม่เข้าเงื่อนไขยังคงเดิม

## เปิดใช้งาน

เปิด `Start_Scanner_YOLO.bat` สำหรับ Full HD, YOLO stream, ภาษาไทย, ปิด sharpening เริ่มต้น หรือใช้:

```powershell
.venv\Scripts\python.exe camera_reader.py --detector yolo --yolo-pipeline stream --res fhd --sharp 0 --lang thai
.venv\Scripts\python.exe yolo_detector.py path/to/image.png --mode yolo --lang thai --save --no-show --dump-stream
```

- `--crop-batch 8`: ปรับจำนวนเซลล์ที่ประมวลผลพร้อมกัน ช่วง 1–32
- `--max-cells 256`: จำกัดจำนวนเซลล์ต่อภาพ
- `--proposal-conf 0.30`: เกณฑ์เสนอ crop ต้องไม่สูงกว่า `--conf`
- `--conf 0.35`: เกณฑ์ยืนยันจุดใน crop
- `--tile-size 0`: ปิด tiles เพิ่มเติมเพื่อลดงาน AI แต่อาจพลาดจุดเล็กในภาพกว้าง
- `--yolo-pipeline stream`: เป็น pipeline เดียวที่รองรับใน branch นี้

เมื่อเลือก YOLO แต่ไม่มี weights ที่โหลดได้ จะรายงานข้อผิดพลาด ไม่มีการสลับไปตรวจสีโดยไม่แจ้ง

## ตรวจ crop และกล้อง

`--dump-stream` สร้าง `output/<ชื่อภาพ>_stream/` พร้อมภาพ crop, `contact_sheet.png` และ `manifest.json` ซึ่งบันทึกบรรทัด ลำดับเซลล์ จุดก่อน/หลังอ่าน crop ความกำกวม การแก้ marker ช่วงสัญลักษณ์ และข้อความ ใช้รายชื่อ crop ใน manifest ของรอบล่าสุดเป็นหลัก

งาน AI ทำใน worker แยกจากการแสดงกล้อง รับเฉพาะเฟรมล่าสุดและประมวลผล crop เป็น batch ส่วนจอแคชกรอบ/ข้อความตามผล AI ไม่วาดใหม่ทุกเฟรม เมื่อเปลี่ยนภาษา ความคม หรือพื้นที่ซูม จะซ่อนผลที่เป็นของการตั้งค่าเก่า ระบบรายงานความเร็ว AI แยกจากลูปแสดงผล ตัวเลขเหล่านี้ไม่ใช่การรับประกัน 60 FPS จากอุปกรณ์

ปุ่ม `P` เก็บภาพดิบของ ROI เป็น `*_raw.png` ควบคู่ภาพผลลัพธ์ ภาพดิบไม่มีกรอบ/ตัวเลขทับ เหมาะสำหรับตรวจและทำ label ภายหลัง ภาพผลลัพธ์อาจมาจาก AI เฟรมก่อนหน้า จึงไม่ใช่ ground truth ของภาพดิบโดยอัตโนมัติ

## ผลที่ตรวจแล้ว

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe tools\diagnostics\benchmark_yolo_stream.py
```

- **46 tests ปัจจุบันผ่าน** ครอบคลุม cell stream, worker, dataset และการฝึก ส่วน tests ของ CV ย้ายไปเก็บเป็นประวัติแล้ว
- **YOLO จริงผ่าน 99/99 ภาพสังเคราะห์**: 33 กรณี × 3 ขนาด (100%, 25%, 20%) ต้องถูกทั้งข้อความและรูปแบบจุดของทุกเซลล์ รวมกรณี `ญา` / `ภ้` สองบรรทัด ระยะเซลล์ 148 px และ ญ ที่มีเซลล์เต็มให้อ้างอิงเพียงตัวเดียว
- ในภาพสังเคราะห์ชุดนี้ จุดเริ่มต้นรัศมี 8 px; ขนาด 20% มีเส้นผ่านศูนย์กลางประมาณ 3.2 px ก่อนผลของการย่อ/หมุน นี่เป็นขนาดในภาพ ไม่ใช่ขนาดอักษรเบรลล์จริงเป็นมิลลิเมตร
- ภาพต้นฉบับของโปรเจกต์ `sample_images/Test_thai_01.png` อ่านเป็น `สวัสดีครับผม` 12 เซลล์
- รายงาน `output/yolo_stream_benchmark.json` เก็บผลรายกรณี เวลา เกณฑ์ confidence รุ่นไลบรารี และ SHA-256 ของ weights

ภาพหน้าจอที่ผู้ใช้แนบมีกรอบ วงกลมช่องว่าง และตัวเลขทับข้อมูลแล้ว เมื่อนำเข้า YOLO ทั้งภาพเกิดจุดเกินและข้อความผิด จึงเก็บเป็น diagnostic ไม่รวมในคะแนนความแม่นยำ ภาพตารางพยัญชนะและสระที่แนบใช้ตรวจรหัส มีวงกลมโปร่งแทนช่องว่างและรูปแบบตาราง จึงไม่ใช่หน้าข้อความจากกล้องสำหรับวัด OBR โดยตรง

## ขอบเขตและ dataset รอบถัดไป

99 ภาพข้างต้นมาจาก 33 กรณีที่ย่อขนาดซ้ำ ไม่ใช่ภาพกล้อง 99 ฉากอิสระ ผลนี้ยืนยัน regression ของ algorithm และ weights ปัจจุบัน ยังไม่ยืนยันความแม่นยำจากกล้องหรือ FPS บน Redxa

การหาเซลล์ยังสมมุติว่าระยะจุดค่อนข้างสม่ำเสมอและภาพเอียงไม่มาก ถ้าทั้งบรรทัดขาดแถวจุดบน/ล่าง หรือไม่มีเซลล์ที่มีสองคอลัมน์ ตำแหน่งกริดอาจกำกวม (`row_ambiguous`, `column_ambiguous`) การจับคู่ตามตารางไม่ใช่พจนานุกรมเดาคำ และกรณีการันต์/marker 356 ยังต้องตรวจบริบทเพิ่มเติมตามเอกสารภาษาไทย

ให้เก็บภาพดิบหลายแผ่น หลายรอบถ่าย แสง ระยะ และความเอียง พร้อม label จุด 1–6, กรอบเซลล์เต็ม, บรรทัด และข้อความที่คนตรวจ แยก train/validation/test ตามแผ่นหรือรอบถ่ายก่อนทำ augmentation เก็บตัวอย่างจุดหาย จุดเกิน และพื้นหลังที่ไม่มีเบรลล์ด้วย ไม่ใช้กรอบ debug เป็นข้อมูลดิบ

อัปเดตรอบ dataset: ทดลองฝึก 1 epoch บนชุดเล็กเพื่อเช็กระบบแล้ว โดยไม่เปลี่ยน weights หลัก ดูรายละเอียดใน `SYNTHETIC_DATASET.md` หลัง algorithm และชุดทดสอบจริงนิ่งแล้วจึงพอร์ตและวัดเวลา/หน่วยความจำบนบอร์ด
